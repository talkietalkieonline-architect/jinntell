# JINNTELL — Ключевые решения

---

## D001: Ребрендинг Talkie-Talkie → Aimigo
**Дата:** Июнь 2025
**Решение:** Проект переименован. Строим с нуля на новом стеке.
**Причина:** Старый проект на vanilla JS стал неуправляемым (5500+ строк в одном файле).

## D002: Технологический стек
**Дата:** Июнь 2025
**Решение:** Next.js + FastAPI + PostgreSQL + Redis
**Причина:** Масштабирование по городам и странам, собственные GPU-фермы, микросервисы в будущем.

## D003: Начинаем с нуля, а не рефакторим
**Дата:** Июнь 2025
**Решение:** Новый проект с чистой архитектурой. Старый код (v0.39) — как референс.
**Причина:** Разбиение старого index.html на модули привело к поломкам. Проще построить правильно.

## D004: Система документации
**Дата:** Июнь 2025
**Решение:** 4 файла документации (ТЗ, Прогресс, Архитектура, Решения) обновляются каждую сессию.
**Причина:** AI-ассистент теряет контекст между сессиями. Документация = память проекта.

## D005: Фазовая разработка
**Дата:** Июнь 2025
**Решение:** 3 фазы — MVP → Голос и режимы → Масштаб
**Причина:** Не утонуть в масштабе. Сначала рабочий продукт, потом расширение.

## D006: Игнорировать "Мир агентов"
**Дата:** Июнь 2025
**Решение:** Концепция "Мир агентов" из старого проекта — ошибочное направление.
**Причина:** Решение владельца проекта. Используем только "Город агентов" (каталог).

## D007: Voice-first UX
**Дата:** Июнь 2025 (Сессия 5)
**Решение:** Основной способ ввода — голос. Текстовое поле скрыто по умолчанию, появляется по кнопке ⌨️.
**Причина:** Платформа идёт к говорящим аватарам с мимикой. Голос — основной UX. Клавиатура на телефоне закрывает треть экрана.

## D008: Кнопка Mute убрана, функция на микрофоне
**Дата:** Июнь 2025 (Сессия 5)
**Решение:** Короткое/длинное нажатие на микрофон = вкл/выкл/always-on/mute.
**Причина:** Освобождаем место для кнопки переключателя ввода.

## D009: Пузыри — пользователь СЛЕВА, агенты СПРАВА
**Дата:** Июнь 2025 (Сессия 5)
**Решение:** Пользователь слева (аватар «Я»), агенты и собеседники справа (аватар с буквой).
**Причина:** Решение владельца проекта. Агенты справа — ближе к правой панели «Команда эфира».

## D010: Бизнес-визия задокументирована
**Дата:** Июнь 2025 (Сессия 5)
**Решение:** Создан BUSINESS_VISION.md — монетизация, аудитории, режимы, коммерческий блок.
**Причина:** AI-ассистент должен понимать полную картину продукта в каждой новой сессии.

## D011: Graceful fallback — фронт работает без бэкенда
**Дата:** Июнь 2025 (Сессия 6)
**Решение:** Все API-вызовы обёрнуты в try/catch. При недоступном бэкенде фронт использует локальные данные (хардкод-агенты, оффлайн-чат, локальная SMS-верификация).
**Причина:** Можно разрабатывать UI без запущенного сервера. Когда Docker поднят — всё заработает автоматически.

## D012: React Context для авторизации (не Redux / Zustand)
**Дата:** Июнь 2025 (Сессия 6)
**Решение:** Единый AuthContext вместо внешнего стейт-менеджера.
**Причина:** Минимум зависимостей на MVP. Авторизация — простой стейт (user + isLoggedIn). Переход на Zustand при усложнении.

## D013: Хуки вместо inline-логики в page.tsx
**Дата:** Июнь 2025 (Сессия 6)
**Решение:** useChat, useAgents — отдельные хуки в /hooks/.
**Причина:** page.tsx был 150+ строк с inline-логикой чата и демо-данными. Теперь чистый компонент композиции.

## D014: Личный чат с агентом — комнаты agent-{id}
**Дата:** Июнь 2025 (Сессия 9)
**Решение:** Каждый агент — отдельная WS-комната `agent-{id}`. Агент загружается из БД при подключении и отвечает через `get_agent_reply()` с полным персонажем.
**Причина:** Переиспользуем существующий WS-менеджер комнат без новых эндпоинтов. Комната `general` = Дворецкий, `agent-{id}` = конкретный агент. Масштабируется на любое количество агентов.

## D015: TopBar переключается между ЭФИР и заголовком агента
**Дата:** Июнь 2025 (Сессия 9)
**Решение:** В общей комнате — бегущая строка ЭФИР. В личном чате с агентом — аватар, имя, профессия, кнопка «Назад».
**Причина:** Как в Telegram — шапка чата показывает с кем говоришь. Бегущая строка не нужна в личном чате.

## D016: Мульти-провайдер LLM (OpenAI + Gemini + Groq)
**Дата:** Июнь 2025 (Сессия 9)
**Решение:** llm.py поддерживает 3 провайдера. Автовыбор по наличию ключей. Каждый агент может работать на своей модели.
**Причина:** Gemini Flash бесплатен для разработки, Groq быстрый, OpenAI качественный. Бизнес платит за GPT-4o, Дворецкий на Gemini бесплатно.

## D017: Курс на собственную LLM-инфраструктуру
**Дата:** Июнь 2025 (Сессия 9)
**Решение:** В перспективе — собственный GPU-сервер с vLLM + Llama/Qwen. Наш `_call_openai()` уже совместим с vLLM API.
**Причина:** Нулевая зависимость от внешних API, себестоимость в 150раз ниже OpenAI. Llama 3.1 8B на 1×RTX 4090 — достаточно для 50-100 агентов. 70B (4-bit quant) на 2×RTX 4090 — качество GPT-4o-mini.

## D018: Голосовой стек — Yandex SpeechKit → Silero → свой XTTS
**Дата:** Июнь 2025 (Сессия 9)
**Решение:** TTS/STT стек: сначала Yandex SpeechKit (API), потом свой XTTS v2 на GPU.
**Причина:** Yandex в 10-50раз дешевле ElevenLabs, лучшие русские голоса. XTTS v2 — клонирование голоса за 6 секунд образца, self-hosted, себестоимость ~$0.001/мин.

## D019: DeepSeek как основной LLM-провайдер
**Дата:** Апрель 2026 (Сессия 11)
**Решение:** DeepSeek V3 (deepseek-chat) — основная модель для всех агентов и Дворецкого. OpenRouter как fallback.
**Причина:** $0.27/M токенов (в 10раз дешевле GPT-4o), качество на уровне GPT-4o, работает из РФ без VPN, OpenAI-совместимый API. На $5 хватит ~100K сообщений.

## D020: OpenRouter как бесплатный fallback
**Дата:** Апрель 2026 (Сессия 11)
**Решение:** Агрегатор OpenRouter с авто-fallback между бесплатными моделями (Gemma 3, Llama 3.3).
**Причина:** Бесплатные модели дают 429 при перегрузке — автоматически пробуем следующую. Работает из РФ, не требует оплаты.

## D021: Модель работы Opus + Sonnet
**Дата:** Апрель 2026 (Сессия 11)
**Решение:** Разделение работы между Claude Opus 4 (архитектор) и Claude Sonnet 3.5/3.7 (исполнитель).
**Причина:** Opus дорогой и медленный, но лучше в архитектуре и анализе. Sonnet быстрый, дешёвый, пишет код не хуже для рутинных задач. Opus готовит ТЗ, Sonnet исполняет, Opus проверяет и деплоит. Экономия ~3-5х на токенах без потери качества.

## D022: Qdrant вместо pgvector для векторной памяти
**Дата:** Май 2026 (Сессия 14)
**Решение:** Qdrant как основной Vector DB. PostgreSQL остаётся для структурированных данных.
**Причина:** Масштаб: 1.5М пользователей × тысячи чанков = миллиарды векторов. pgvector не вытянет. Qdrant: шардирование, фильтрация по tenant_id, горизонтальное масштабирование. Отдельная коллекция на каждого контрагента.

## D023: Трёхуровневая архитектура данных: Коммуникатор → Коннектом → Синцитий
**Дата:** Май 2026 (Сессия 14)
**Решение:** Коммуникатор (UI) → Коннектом (Qdrant index, owner_type: user|business_agent) → Синцитий (протокол обмена между Коннектомами).
**Причина:** Разделение ответственности. Личная память не смешивается с корпоративной. Дворецкий оркестрирует обмен через Синцитий.

## D024: GPT-SoVITS как основной TTS-движок
**Дата:** Май 2026 (Сессия 14)
**Решение:** GPT-SoVITS — основной (библиотека + клон). Coqui XTTS v2 — fallback. Tortoise-TTS убран из стека (слишком медленный).
**Причина:** GPT-SoVITS быстрый, качественный, клонирует по 1 минуте образца. Tortoise 10-30 сек на фразу — не подходит для реалтайм.

## D025: Библиотека голосов — управляемая из админки
**Дата:** Май 2026 (Сессия 14)
**Решение:** Админ загружает лицензированные голоса в каталог. Бизнес/пользователи выбирают. Клонирование = Premium B2C.
**Причина:** Контроль качества, лицензионная чистота, монетизация клона.

## D026: Haystack 2.0 для RAG pipeline
**Дата:** Май 2026 (Сессия 14)
**Решение:** Haystack 2.0 вместо LangChain/LlamaIndex.
**Причина:** Production-ready пайплайны, нативная интеграция с Qdrant, парсинг PDF, подходит под объёмы 75К агентов + 1.5М пользователей.

## D027: Режим "Офис" → "Работа"
**Дата:** Май 2026 (Сессия 14)
**Решение:** Переименование "Офис" → "Работа". Пользователь видит агентов от разных компаний (работа + свой бизнес). Комнаты как в "Общении".
**Причина:** Один человек может работать в нескольких компаниях + иметь свой бизнес. "Работа" шире чем "Офис".

## D028: Режим "Дорога" — новый режим платформы
**Дата:** Май 2026 (Сессия 14)
**Решение:** AI-помощник водителя. Фоновый режим поверх навигатора. GPS + карта опасностей + помощь ГИБДД + чёрный ящик + вызов юриста.
**Причина:** Магнит для привлечения B2C-пользователей (базовый бесплатно). Данные: парсинг + партнёрство ГИБДД + краудсорсинг с фото-верификацией.

## D029: Мультиязычность с дня запуска Whisper
**Дата:** Май 2026 (Сессия 14)
**Решение:** Faster-Whisper Large-v3 (99 языков). Первая новая страна: Грузия (~6 мес).
**Причина:** Мировое масштабирование, нативные приложения Android + iOS.

## D030: Умное сохранение в Коннектом (не всё подряд)
**Дата:** Май 2026 (Сессия 14)
**Решение:** Дворецкий спрашивает пользователя: "Что сохранить в память?" Пользователь подтверждает → факты векторизуются.
**Причина:** Не хотим мусор как в Telegram. Экономия ресурсов (не векторизуем всё подряд) + контроль пользователя над своей памятью.

## D031: Бизнес-модель B2B: 35К абонентская + 150К депозит
**Дата:** Май 2026 (Сессия 14)
**Решение:** Тариф: 35,000р абонентская + 150,000р депозит на токены/голос. Цель: с каждых 10 агентов — фонд на выкуп железа.
**Причина:** Формирование фонда на собственную инфраструктуру. Автономность завода.

## D032: Динамические комнаты + несколько агентов в комнате
**Дата:** Май 2026 (Сессия 14)
**Решение:** Комнаты создаются динамически (Дворецкий советует / пользователь вручную). Несколько агентов в одной комнате. Дворецкий отключаем.
**Причина:** Гибкость UX. Комнаты сохраняются с историей, можно вернуться через месяц/год.

## D033: Нет корзины/оплаты внутри Aimigo
**Дата:** Май 2026 (Сессия 14)
**Решение:** Агент консультирует → даёт ссылку на сайт контрагента. Покупка на стороне.
**Причина:** Не гонять чужие деньги через нас. Меньше юр. рисков.

## D034: React Native для мобильных приложений
**Дата:** Май 2026 (Сессия 14)
**Решение:** React Native (Expo). Переиспользуем TypeScript логику (hooks, API, типы). ~1 мес после стабилизации веб.
**Причина:** iOS не поддерживает Web Speech API в PWA. Режим "Дорога" требует натив. Мировое масштабирование.

## D035: Матрица типов агентов (5 типов)
**Дата:** Май 2026 (Сессия 14)
**Решение:** system / promo / business / corporate / citizen. Расширяемо.
**Причина:** Разные права, видимость, биллинг. Системные на отдельной вкладке админки.

## D036: Отдельная авторизация контрагента (логин/пароль)
**Дата:** Май 2026 (Сессия 14)
**Решение:** Контрагент входит по логину/паролю (не SMS). Один человек может быть и пользователем и контрагентом.
**Причина:** Разделение потоков. Бизнес — отдельная сущность с балансом, юр. данными, агентами.

## D037: Дизайн — светлая тема, современный, удобный
**Дата:** Май 2026 (Сессия 14)
**Решение:** Полный редизайн после запуска. Светлая тема (НЕ тёмная). Ультра удобный и современный.
**Причина:** Текущий dark UI — временный. Сначала рабочая система, потом дизайн.

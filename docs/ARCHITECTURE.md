## 1. Что такое Aimigo

Aimigo — **завод по производству AI-агентов**. Платформа принимает заказы от бизнеса (контрагентов), создаёт голосовых AI-агентов, размещает в экосистеме, зарабатывает на каждом разговоре.

```
КОНТРАГЕНТ (бизнес)
  │ оплачивает → получает ЛК → выбирает болванку → заливает знания
  ↓
ЗАВОД JINNTELL
  │ берёт болванку + знания + голос + манеры + внешность
  │ собирает готового агента
  ↓
ПОЛЬЗОВАТЕЛЬ
  │ открывает aimigo.online → говорит с агентом голосом
  ↓
КОНТРАГЕНТ видит аналитику в ЛК
```

## 2. Пять главных агентов платформы

### 2.1 Дворецкий (РЕАЛИЗОВАН)
- Навигатор и помощник пользователя
- Комната `general` — первый экран после входа
- Настройки: Redis `butler:settings` + админка

### 2.2 Слушатель (НЕ РЕАЛИЗОВАН)
- Невидимый аналитик, работает в фоне в КАЖДОЙ комнате
- Пользователь его НЕ видит
- Анализирует: качество ответов, настроение, тренды, уход от темы
- Пишет саммари → таблица `dialog_summaries`
- Формирует отчёты для контрагента
- Алертит админу о проблемных агентах
- Реализация: Celery-задача после каждых N сообщений

### 2.3 Контролёр / AI-Админ (НЕ РЕАЛИЗОВАН)
- Следит за здоровьем завода, живёт только в админке
- Мониторит: CPU/RAM/GPU, WS-сессии, очередь LLM, расход токенов, стоимость
- Прогнозирует нагрузку, рекомендует оптимизации
- Алертит при сбоях и пиках
- Реализация: Prometheus + Celery + Redis метрики

### 2.4 Болванки агентов (ЧАСТИЧНО)
- Шаблоны: Консультант, HR, ПДД, Техподдержка, Риелтор, Юрист, Тренер
- В БД: `is_template: bool` + `template_id`

### 2.5 Личный агент пользователя (ЗАЛОЖЕНО)
- Персональный ассистент, по подписке (B2C)
- Использует семантическую память (L5)

Контрагент настраивает в ЛК (6 табов в BusinessDashboardModal):

```
AI / Мозг:     LLM-модель, system prompt, приветствие, база знаний (50К)
Голос:         voice_id, voice_speed, voice_pitch, будущее: клон (XTTS)
Манеры:        style (formal/friendly/playful/strict), temperament, humor, emoji
Внешность:     face, hair, skin, body (будущее: аватары с мимикой)
Одежда:        style (formal/casual/sport/uniform), top/bottom/shoes/accessory
Знания:        текст, URL, файлы (PDF)
```

## 5. Режимы платформы

Приоритет: Общение ✅ → Работа → Шопинг → Обучение → Дорога → Прогулка

### ОБЩЕНИЕ (РЕАЛИЗОВАН)
Дворецкий + Город Агентов + личные чаты + голос + текст + медиа + кружочки

### РАБОТА (НЕ РЕАЛИЗОВАН, ПРИОРИТЕТ) [бывший "Офис"]
- Корпоративное пространство, только private-агенты (Ghost Agents)
- Пользователь переключает режим → видит только агентов из своего whitelist
- Агенты могут быть от РАЗНЫХ компаний (работа + свой бизнес)
- Комнаты как в "Общении": "Адаптация ООО Полимер", "Юрист Полимер", "Мой бизнес - бухгалтер"
- Контрагент управляет whitelist в ЛК (добавляет/убирает телефоны)
- Ghost Agents видны в Городе как "закрытые", но доступны только по whitelist
- Доступ через agent_access

### ШОПИНГ (НЕ РЕАЛИЗОВАН)
- Агенты-продавцы с каталогами, карточки товаров, корзина, заказы
- Интеграция с 1С контрагента (остатки, цены, сроки годности)
- Новые сущности: products, orders, agent_catalog

### ОБУЧЕНИЕ (НЕ РЕАЛИЗОВАН)
- Агент-лектор, тренажёр, экзаменатор, курсы, прогресс
- Новые сущности: courses, lessons, progress

### ДОРОГА (НЕ РЕАЛИЗОВАН, нужно мобильное приложение)
- AI-помощник водителя, работает в фоне поверх навигатора (PWA → нативное приложение)
- Keep-alive через тихий аудиоканал (чтобы OS не убивала процесс)
- Считывает GPS-координаты из навигатора
- Предупреждает об опасных участках (места ДТП, дети, сложные развязки)
- Информирует о камерах, постах ГИБДД, ПДД-ловушках
- Источники данных: парсинг открытых данных + партнёрство с ГИБДД + краудсорсинг (фото-верификация)
- Помощник при остановке ГИБДД: слушает, рекомендует, ссылки на закон
- "Чёрный ящик": запись аудио в память как доказательство
- Помощь при ДТП: инструкции, вызов патруля (будущее: связь с агентом полиции)
- Подключение юриста/адвоката по видео при спорных ситуациях
- Базовый функционал бесплатно (магнит), Premium: юрист, чёрный ящик, видео-адвокат

### ПРОГУЛКА (БУДУЩЕЕ, нужно мобильное приложение)
- Гео-привязанные агенты на карте, push-уведомления
- Новые сущности: agent_locations, geofences

## 6. Кружочки (видеосообщения как в Telegram)

## 7. Память — 5 уровней + Коннектом

```
L1: ГОРЯЧАЯ (Redis) — сессии, typing, кэш сообщений        [РЕАЛИЗОВАНО]
L2: ТЁПЛАЯ (PostgreSQL) — сообщения, агенты, биллинг       [ЧАСТИЧНО]
L3: МЕДИА (S3/MinIO) — фото, видео, голосовые, кружочки   [НЕ РЕАЛИЗОВАНО]
L4: ХОЛОДНАЯ (архив) — сообщения старше 6 мес              [НЕ РЕАЛИЗОВАНО]
L5: СЕМАНТИЧЕСКАЯ (Qdrant) — RAG, embeddings, Коннектомы   [НЕ РЕАЛИЗОВАНО]
```

Контекст LLM сейчас: последние 10 сообщений.
Цель: prompt + саммари Слушателя (L2) + RAG знаний (L5) + последние 20 сообщений.

### Трёхуровневая архитектура данных: Коммуникатор → Коннектом → Синцитий

```
КОММУНИКАТОР (Interface)
  │ PWA/приложение. Только ввод-вывод.
  ↓
КОННЕКТОМ (Personal/Business Brain)
  │ Стандартизированный модуль векторной памяти (Qdrant index).
  │ Атрибут: owner_type = [user | business_agent]
  │
  ├─ User Connectome: личный "слепок" знаний и предпочтений человека
  │   • Дворецкий спрашивает: "Что сохранить в память?" (не мусор)
  │   • Пользователь подтверждает → факты векторизуются
  │
  └─ Business Agent Connectome: профессиональная база знаний агента
      • RAG из загруженных документов + данные 1С
      • Read-only: данные НЕ используются для fine-tuning
  ↓
СИНЦИТИЙ (Network/Protocol)
  │ Единая среда и протокол обмена между Коннектомами.
  │ User Connectome ←→ Business Connectome (через Дворецкого)
  │ Безопасный обмен с проверкой whitelist.
```

### Изоляция корпоративных данных (4 уровня)
1. **Qdrant** — отдельная коллекция на контрагента (не payload filtering)
2. **RAG read-only** — корпоративные данные только для retrieval, НИКОГДА для fine-tuning
3. **Whitelist-валидация** — проверка ДО обращения к LLM, на уровне бэкенда
4. **Context Separation** — личный Коннектом ≠ корпоративная база, не смешиваются без явного действия

### Семантический Кэш ("Золотые ответы")
- База эталонных ответов для типовых юридических/технических вопросов
- Перед обращением к LLM → поиск по cosine similarity > порог → мгновенная выдача
- Экономия токенов GPU (B200)

## 9. Голосовой завод — TTS/STT

Сейчас: Web Speech API браузера ($0, роботизированный).
Цель: серверный TTS → аудиофайл → кэш S3 → воспроизведение (микрофон на паузе).

### Библиотека голосов
- Каталог лицензированных голосов, управляется из админки
- Бизнес и пользователи ВЫБИРАЮТ из каталога (не загружают свои)
- Клонирование голоса — только Premium B2C подписка (модуль "Личный голос" для личного агента)
- Филлеры ожидания: "Секунду...", "Хм, дайте подумать..." пока генерирует (max 2-3 сек)

### STT (Speech-to-Text)
| Фаза | Технология | Примечание |
|------|-----------|------------|
| 1 сейчас | Web Speech API (браузер) | $0, ограничения iOS |
| 2 (облако) | Cloud Whisper API | Промежуточный этап |
| 3 (6-9 мес) | Faster-Whisper Large-v3 (свой GPU) | Мультиязычный, 99 языков |

### TTS (Text-to-Speech)
| Фаза | Технология | Примечание |
|------|-----------|------------|
| 1 сейчас | Web Speech API | $0, роботизированный |
| 2 (1-3 мес) | Yandex SpeechKit | ~$1.5/1M символов |
| 3 (6-9 мес) | GPT-SoVITS (свой GPU) | Основной: библиотека + клонирование по 1 мин |
| 4 (fallback) | Coqui XTTS v2 | Резервный TTS-движок |
| 5 (12-24 мес) | Видео-аватары | ~$1000-2000/мес |

## 11. Биллинг

```
Стоимость = (токены LLM × тариф) + (символы TTS × тариф) + (STT × тариф) + наценка
```
При балансе 0 → агент говорит "пополните баланс".

## 17. Интеграция с 1С

- Контрагент подключает свою 1С через API-ключ
- При настройке оговаривается: какие данные открыть агенту (остатки, цены, сроки годности, поступления)
- Данные из 1С → векторизуются в Qdrant (Business Connectome)
- Интервал синхронизации настраивается в ЛК контрагента: от 1 часа до 1 раза в день
- Пример: магазин продуктов = каждый час; магазин сумок = 2 раза в день

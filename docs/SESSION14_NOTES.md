# Сессия 14 — Заметки (вопросы 21-40)

## Семантический Кэш (Вопрос 21)
- Автоматическое наполнение: система выявляет повторяющиеся вопросы и кэширует лучшие ответы
- Ручное наполнение: контрагент/админ добавляет эталонные FAQ
- Перед вызовом LLM → cosine similarity → если высокое совпадение → ответ без токенов
- Особенно эффективно для ПДД, юридических, технических вопросов
- Экономия GPU + мгновенный ответ (0мс вместо 2-3 сек)

## Бизнес-модель B2B (Вопросы 22-24)
- 35,000₽/мес — абонентская за 1 агента (любой тип)
- 150,000₽ — стартовый депозит за 1 агента (расходуется на трафик)
- Наценка x2: покупаем у Яндекса 1500₽/1М токенов → продаём по 3000₽/1М
- Маржа 50% → фонд на железо
- Корпоративная скидка — индивидуальная, поле в админке (контрагент не видит)
- 5 агентов = 5×35К + 5×150К (со скидкой для крупных)
- Стратегия: быстрее купить железо → себестоимость падает

## Монетизация B2C — подписки по режимам (Вопрос 24)
### Режим "Дорога": ~450₽/мес
- Доп агенты: автоюрист, автостраховщик

### Режим "Шоппинг": подписка
- Личный костюмер, стилист, агент секонд-хенд (продажа старой одежды)

### Режим "Прогулка": подписка
- Спецпредложения, доп скидки от сервиса
- Агенты-зазывалы: тот же бизнес-агент но с манерой "приглашение зайти"
- Настройка в ЛК контрагента: "поведение в режиме Прогулка"

### Режим "Общение": 3 тарифа (390-990₽/мес)
- RAG-память (наличие + объём хранения)
- Агент "Я" (виртуальная копия в Городе)
- Клон голоса, внешность, наряды, генерация лайв-видео
- + бюджет на разговоры агента "Я" в Городе

### Самозанятые (девочка-маникюрщица): ~6900₽ + бюджет
- Отдельная категория для мелкого бизнеса через агент "Я"
- Дворецкий НЕ показывает их в выдаче
- Сами раздают ссылки/визитки со своим линком

## Агент "Я" (Вопросы 29-30)
- Социальная копия пользователя в Городе (знакомства, флирт, поклонники)
- Настройки прав: общение с агентами / с пользователями / обоими
- Работает автономно + отчитывается владельцу
- Видимость (public/link_only/private) — настраивает пользователь
- Тариф определяет наличие/отсутствие (не видимость)
- Защита: агент "Я" ≠ консультант. Дворецкий по коммерческим запросам ищет только бизнес-агентов

## Дворецкий — роль (Вопрос 33-34)
- Рабочая лошадка: поиск агентов/товаров, приглашение в комнату, мониторинг
- Находит агентов в Городе по запросу пользователя
- Приглашает/вытаскивает агента в комнату пользователя
- НЕ говорит за агентов (слушает, сохраняет контекст в RAG)
- Может озадачивать агентов: "следи за скидками на кроссовки"
- Запоминает сделки, покупки ("эти кроссы вы купили год назад")

## Комнаты — динамическая модель (Вопросы 34-36)
- Несколько агентов в одной комнате — ДА
- Пользователь распределяет агентов по комнатам сам
- Дворецкий можно отключить в конкретной комнате
- Комнаты создаются динамически (по рекомендации Дворецкого или вручную)
- Дворецкий умный: советует отдельную комнату для долгосрочных бесед
- Комнаты сохраняются с историей, можно вернуться через месяц/год
- Проактивность: агент может "ждать" пользователя с новостью (скидка)
- Дворецкий уведомляет: "вас ждёт агент Adidas" → пользователь решает

## Уведомления (Вопрос 36)
- Три канала параллельно:
  1. Дворецкий — напоминает голосом/текстом (с разрешения пользователя)
  2. ЭФИР (бегущая строка) — добавляет сам по факту
  3. Push-уведомления — для мобильных/PWA

## Согласие на рекламу / 152-ФЗ (Вопрос 38)
- Агент спрашивает: "Хотите получать акции?" → кнопка на экране
- Доп подтверждение через код (двойной opt-in)
- Два списка у маркетолога: "С разрешением" / "Без"
- Маркетолог видит: телефон, ник, пол, возраст (реальные, не персонаж)
- Пользователь в настройках: список подписок с рычажками вкл/выкл

## Оплата/заказы (Вопрос 39)
- НЕТ корзины/оплаты внутри Aimigo
- Агент консультирует → даёт ссылку на сайт/приложение контрагента
- Покупка на стороне. Мы не касаемся чужих денег.

## Видеопрезентация агента (Вопрос 40)
- Фаза 1: контрагент загружает готовое видео MP4 (мы помогаем снять)
- Фаза 2: генерация видео по промпту (добавим в ЛК)
- Работает для бизнес-агентов и пользовательских "Я"

## ЛК Контрагента — полная структура (Вопрос 37+)
### Главное окно:
- Юр. данные (ООО, ИНН, адрес, реквизиты, ФИО контактного, ФИО директора)
- Список агентов (действующие + на тесте/не в городе)
- Баланс, средний расход/день, прогноз расходов для пополнения
- Подключённые модели, голосовые, затраты по железу (карты, RAM)

### Вкладка "Аналитика по агенту":
- Сколько поговорил, какие вопросы
- Провал в чаты для анализа
- Баланс по агенту, статистика трат по дням
- Динамика нагрузки в течение дня
- Оценки от пользователей

### Вкладка "Пользователи" (маркетинг):
- Списки взаимодействовавших (с разрешением / без)
- Телефон, ник, пол, возраст

### Вкладка "Внутренние агенты" (Ghost):
- Скрытые агенты, о чём говорили
- Whitelist (белый список пользователей)

### Настройки каждого агента:
- Внешность, одежда, голос, модель, манеры, знания (6 табов)
- Роль + контекст с правилами (чтобы не рассуждал о большом взрыве)
- Окно контекста для вставки текста
- Прикрепление файлов (Word, PDF) со знаниями
- Скилы (скрипты продаж для продавцов/консультантов)
- Поведение в режиме "Прогулка" (зазывала)
- API 1С (ключ + интервал синхронизации + выбор данных)
- Видеопрезентация (загрузка MP4 / генерация)
- Подключения/ссылки (куда вести при покупке/бронировании)
- Фото товаров (API 1С или ручное наполнение RAG)
- Образованность, характер (определяют личность)

### Отчёты:
- Формирует агент Слушатель + агент Контролёр
- Выгрузка отчётов

### Архитектура ЛК:
- Заложить расширяемость — удобно добавлять вкладки/сущности не ломая целое

## Интеграция с 1С (Вопрос 31)
- Контрагент вводит API-ключ в ЛК (его ответственность)
- Настройка данных — совместно (мы + контрагент, тестируем)
- Лимит на объём данных одного агента (чтобы не тупил)
- Гипермаркет = 5-10 агентов по отделам + хостес (стимулирует покупку агентов)
- Если нужно писать обработку для 1С — напишем

## Агент-хостес (Вопрос 32)
- Связующий агент для крупных бизнесов (гипермаркеты)
- Хостес сам ответит на простое (дёрнув RAG специалиста)
- Переключит на специалиста при сложном запросе
- Хороший UX + монетизация (больше агентов)

## Нативные приложения (Вопрос 27)
- React Native (Expo) — переиспользуем TypeScript логику
- Таймлайн: ~1 месяц после стабилизации веб-версии
- Android + iOS
- Необходимо для: режим "Дорога", iOS микрофон, push-уведомления

## Вопросы 41-48

### Онбординг контрагента (Вопрос 41)
1. Админ в админке: создаёт контрагента → логин/пароль → добавляет болванки
2. Контрагент пополняет баланс
3. Админ передаёт доступ к ЛК
4. Контрагент настраивает агентов

### Контроль оплаты (Вопрос 42)
- Кнопка в админке: "Отключить агента" (ручная)
- Автоотключение при балансе 0
- Сообщение пользователю:
  - Бизнес-агент: "Свяжитесь с [компания] напрямую"
  - Прочие: "Извините, временно недоступен"
  - Кастомное: контрагент пишет своё ("Я в отпуске!")

### Болванки агентов — стартовые 7 штук (Вопрос 43)
1. Консультант магазина
2. Менеджер по доставке (онлайн бронирование)
3. HR-агент компании
4. Тренер-коуч
5. Администратор магазина
6. Агент по претензиям
7. Агент по качеству обслуживания
Далее добавляем по мере обучения.

### Вход контрагента (Вопрос 44-46)
- Через Город Агентов → "Для бизнеса" → ЛК (как сейчас)
- Отдельный логин/пароль (НЕ SMS)
- Один человек может быть и пользователем (SMS) и контрагентом (логин/пароль)
- Разные сессии, не смешиваются

### Матрица типов агентов (Вопрос 47)
1. **Системные** (отдельная вкладка в админке): Дворецкий, Слушатель, Контролёр
2. **Промо** (наши, для аудитории): ПДД, Ремонт, Юрист — бесплатные, наращивают базу
3. **Бизнес** (созданы контрагентом): публичные коммерческие
4. **Корпоративные/Ghost** (созданы бизнесом): скрытые, для внутренних сотрудников
5. **Жители** (копии пользователей): агент "Я"
Иерархия расширяемая.

### Модерация / безопасность (Вопрос 47)
- Агент-Слушатель: онлайн-контроль всех разговоров
- Дисклеймер: "информация сгенерирована AI"
- Полное тестирование безопасности после создания основной системы

### Админка: вкладка "Общая картина" (Вопрос 47)

### Принципы (Вопрос 48)
1. **Расширяемость** — новые режимы, блоки, сервисы добавляются легко
2. **Система плагинов** — внешние сервисы (Spotify и др.) через единый API
3. **Безопасность** — отдельный этап тестирования после основной системы
4. **Дизайн** — ультра удобный, современный, НЕ тёмный (светлая тема!)
5. **Сейчас = результат** — рабочая система → запуск → дизайн-ревизия
